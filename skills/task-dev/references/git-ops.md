# git 前提の確定（設定・ブランチ・コミット・push）【task-dev 専用】

> **読み込むタイミング**: ステップG（git 前提の確定）の着手時。**両モードで必ず読み込みます**。
> 本ファイルを読まずにブランチ作成・コミット・push を行わないこと。既定値・判別条件・リトライ規約を記憶や推測で再構成すると、**遠隔へ反映される操作を推測で行う**ことになります。
>
> **主体はメイン会話に限られます。** 実装・レビュー・修正の委譲先は、従来どおり `git add` / `git commit` / `git push` / ブランチ操作を**一切行いません**（サブエージェントの禁止事項は緩めません）。ブランチ作成・コミット・push はすべてメイン会話の責務です。

## 0. この規約が適用される範囲

| モード | ブランチ作成 | コミット | push |
|---|---|---|---|
| 単一タスクモード | `branch.create` に従う（既定: **する**） | `commit` に従う（既定: **する**。ステップC） | `push` に従う（既定: **環境判別**。GB-7） |
| 複数タスクモード | **行わない**（`GB-23`。警告のうえ起動時のブランチへコミット） | `commit` に従う（既定: **する**。6-3 (d)） | 同上・**タスクごとのコミット直後** |

## 1. 設定の解決（`GB-1`〜`GB-6`）

設定は**プロジェクト単位のファイル**で行います。**利用者向けの環境変数は設けません**（環境変数は層が見えず、どの設定でその挙動になったのかを後から追跡できないため）。

| 優先度 | ファイル | 性質 |
|---|---|---|
| 1（最優先） | `<PROJECT_ROOT>/.claude/task-skills.local.json` | 個人の環境ごとの設定。`.gitignore` への登録を**推奨**する（前提にはしない） |
| 2 | `<PROJECT_ROOT>/.claude/task-skills.json` | コミットして共有する、チーム共通の設定 |
| 3 | 既定値（`GB-2`） | 下記 |

```json
{
  "branch": {
    "create": true,
    "prefix": "feature/"
  },
  "commit": true,
  "push": true
}
```

| # | 規則 |
|---|---|
| **GB-1** | **マージはキー単位**。ローカル層に書かれたキーだけが上位優先で上書きされ、書かれていないキーは下位層（共有層 → 既定値）が残る。`branch` のようなネストしたオブジェクトも**キー単位**で合成する（`branch.prefix` だけをローカル層に書いても `branch.create` は下位層の値が生きる） |
| **GB-2** | 読み取るキーと既定値は次の4つのみ: `branch.create` = **true** ／ `branch.prefix` = **`feature/`** ／ `commit` = **true** ／ `push` = **環境判別（`GB-7`〜`GB-9`）**。`branch.prefix` に空文字列を指定すればブランチ名はタスク名そのものになる |
| **GB-3** | 設定ファイルは**読むだけ**。本スキルは作成も書き換えも行わない（`.claude/task-skills*.json` は書き込み禁止対象・5-16） |
| **GB-4** | JSON としてパースできない層は**その層全体を無視**して警告を表示し、加えて `push` を **false へ倒す**（利用者の意図を読み取れない状態で遠隔へ反映しないため）。ファイルが存在しないことは正常であり、警告しない |
| **GB-5** | 未知キー・型不正のキーは**当該キーのみ無視**して警告する（他のキーは有効） |
| **GB-6** | **整合性規則**: `commit` が false のとき `push` は成立しない。警告を表示して `push` を強制的に false として扱う（**設定ファイルは書き換えない**） |

> **`.gitignore` への登録を挙動の前提にしないこと。** `.local.json` が ignore されているか否かでスキルの挙動を変えてはいけません。リポジトリごとに `.claude/` の ignore 方針が異なり、登録漏れが「エラー」ではなく「意図の逆転」として静かに現れるためです。ignore 登録は運用上の推奨であり、設計の前提条件ではありません。

**読み取りの例**（存在しない層は空として扱う。1回の Bash にまとめる）:

```bash
cd <PROJECT_ROOT> && \
for f in .claude/task-skills.local.json .claude/task-skills.json; do
  printf '=== %s ===\n' "$f"
  test -f "$f" && cat "$f" || echo '(不在)'
done
```

## 2. 実行環境の判別と `push` の既定値（`GB-7`〜`GB-9`）

| # | 規則 |
|---|---|
| **GB-7** | `push` が**どの層の設定ファイルにも書かれていない場合に限り**、実行環境の判別から既定値を決める。**どの層であれ明示されていれば、判別結果がそれを上書きすることは一切ない** |
| **GB-8** | 判別に使う信号は下表の4つ。**存在するか否かの2値**で判定し、値が空文字列・`false`・`0` の場合は**不在**として扱う |
| **GB-9** | 判別結果は**3値**とし、2値へ丸めない。判別不能は `push` を行わず、**目立つ警告**を表示する |

| 信号 | ローカル | クラウド | 役割 |
|---|---|---|---|
| `CLAUDECODE` | `1` | `1` | **対照**。不在なら Claude Code 配下で実行されていない |
| `CLAUDE_CODE_REMOTE` | 不在 | `true` | **主信号** |
| `CLAUDE_CODE_CONTAINER_ID` | 不在 | `container_...` | 副信号 |
| `CCR_AGENT_PROXY_ENABLED` | 不在 | `1` | 副信号（`/root/.ccr/` ディレクトリの存在でも代替可） |

| 判別 | 条件 | `push` の既定値 | 表示 |
|---|---|---|---|
| **クラウド** | 主信号が存在する、**または**副信号が2つとも存在する | **true** | 通常表示 |
| **ローカル** | `CLAUDECODE` が存在し、かつ主信号・副信号が**すべて不在** | **false** | 通常表示 |
| **判別不能** | 上記のいずれにも当てはまらない（副信号が1つだけ、`CLAUDECODE` 自体が不在、など） | **false** | **警告（7-1）** |

> **`CLAUDE_CODE_ENTRYPOINT` は判別に使わないこと。** ローカルは `cli`、クラウドは `remote_desktop` が観測されていますが、クラウドセッションはブラウザ・モバイル・`claude --cloud`・スケジュール実行からも起動でき、**値域が開いています**。「`cli` 以外ならクラウド」という判定は未観測の値に賭けることになります。表示・ログへの記録は有用なので、**参考情報としてのみ**扱ってください。
>
> **これらの環境変数は公開仕様ではなく、将来変更されうるものです。** したがって「判別が失敗したときに何が起きるか」が設計の中心です。**判別不能のときは push しない。ただし未 push のコミットが残る場合は、成果が失われうることを警告として表示する**（`GB-22`）。将来 `CLAUDE_CODE_REMOTE` が廃止されても、「黙って成果が消える」ではなく「警告が出て手動 push を促される」へ劣化します。**この劣化の方向性を壊さないこと。**

**判別の例**（1回の Bash で信号と参考情報をまとめて取得する）:

```bash
printf 'CLAUDECODE=[%s] REMOTE=[%s] CONTAINER=[%s] PROXY=[%s] CCR_DIR=[%s] ENTRYPOINT=[%s] BASE_REF=[%s]\n' \
  "${CLAUDECODE:-}" "${CLAUDE_CODE_REMOTE:-}" "${CLAUDE_CODE_CONTAINER_ID:-}" \
  "${CCR_AGENT_PROXY_ENABLED:-}" "$(test -d /root/.ccr && echo yes)" \
  "${CLAUDE_CODE_ENTRYPOINT:-}" "${CLAUDE_CODE_BASE_REF:-}"
```

## 3. ブランチの決定・作成・再利用（`GB-10`〜`GB-16`）

| # | 規則 |
|---|---|
| **GB-10** | ブランチ名は `<branch.prefix><task_name>`（例: `feature/n123`）。`branch.create` が false なら作成も切替も行わず、カレントブランチのまま作業する |
| **GB-11** | 起点は**作業開始時点のカレントブランチの最新コミット**（`HEAD`）。`main` / `develop` のような統合ブランチ名を決め打ちしない（利用側リポジトリごとに名称が異なるため） |
| **GB-12** | 作成の前に `git check-ref-format --branch <name>` で妥当性を検証する。**不合格ならブランチを作らずエラー終了**（`E-37`）。タスク名は `^[A-Za-z0-9._-]+$` を通っても、先頭・末尾のドット、`..`、`.lock` 末尾などは git のブランチ名として不正でありうる。中途半端な状態を残さないため、**ファイル作成・実装には一切着手しない** |
| **GB-13** | 既存ブランチは**再利用する**（下表） |
| **GB-14** | 再利用時に**起点ブランチの内容を自動マージしない**。既存ブランチが遅れていてもそのまま使い、状態を表示するだけにする（勝手なマージは衝突解決という重い判断を暗黙に持ち込むため） |
| **GB-15** | 作成・切替は**事前検証を通過した後、実装に着手する前**に1回だけ行う。以降スキルはブランチを切り替えない（**終了時に起点ブランチへ戻すこともしない**。戻すと未 push のコミットが利用者から見えなくなる） |
| **GB-16** | カレントブランチが既に `branch.prefix` で始まり、かつ作成対象と異なる場合は**警告を表示して続行**する（別タスクのコミットを起点に含めることになるため）。**自動で起点を変更しない**（どのブランチから分岐すべきかは利用者の判断） |

| 状況 | 検出 | 挙動 |
|---|---|---|
| ローカルに同名ブランチが存在 | `git rev-parse --verify --quiet refs/heads/<branch>` | `git checkout <branch>` して続行 |
| リモートにのみ存在 | `git ls-remote --exit-code --heads origin <branch>` | `git fetch origin <branch>` → `git checkout -b <branch> --track origin/<branch>` して続行 |
| どちらにも無い | 上記2つがいずれも不成立 | `git checkout -b <branch>`（カレントブランチの最新コミットが起点） |

> リモート照会（`git ls-remote` / `git fetch`）が**ネットワーク起因で失敗**した場合は、`GB-20` と同じバックオフでリトライします。最終的に失敗したら「リモートには無い」と断定せず、**ローカル作成へ倒す前に警告を表示**してください（同名のリモートブランチがあるのに新規作成すると、後続の push が non-fast-forward で失敗します）。

## 4. 作業開始前の表示（`GB-17`〜`GB-18`）【省略・要約禁止】

| # | 規則 |
|---|---|
| **GB-17** | **実際に使うブランチ名・起点・コミットの有無・push の有無・その判断根拠を、作業開始前に必ず表示する**。黙って分岐しない |
| **GB-18** | `CLAUDE_CODE_BASE_REF`（セッションの指定ブランチ）が取得でき、かつ作成するブランチと異なる場合は、**推測ではなくその値を明示して報告する**。未設定なら報告を省く |

```
ブランチ: <branch>（新規作成 / 既存を再利用（ローカル） / 既存を再利用（リモート追跡） / 作成せず現在のブランチ）
  起点: <起点ブランチ名> @ <短縮 SHA>
コミット: する / しない ／ push: する / しない
判断根拠: <.claude/task-skills.local.json（push を明示） / .claude/task-skills.json（commit を明示） / 実行環境の判別 / 既定値>
実行環境: <クラウド / ローカル / 判別不能>（信号 CLAUDE_CODE_REMOTE=<有 / 無> ・ CLAUDE_CODE_CONTAINER_ID=<有 / 無> ・ CCR_AGENT_PROXY_ENABLED=<有 / 無> ／ 参考 CLAUDE_CODE_ENTRYPOINT=<値 / 未設定>）
セッション指定ブランチ: <CLAUDE_CODE_BASE_REF の値> — 本スキルの指定を優先します
```

> **セッションの指定ブランチとの関係**: クラウドセッションでは「指定ブランチで開発し、明示的な許可なく他ブランチへ push しない」という指示が入ることがあります。**本スキルのブランチ指定は、利用者が設定ファイルで与えた明示的な許可であり、セッションの指定ブランチの指示に優先します。** ただし push 先は `origin/<本スキルが決定したブランチ>` ただ1つに限られ、他ブランチへは決して push しません（`GB-19`）。

## 5. コミットと push（`GB-19`〜`GB-22`）

コミットそのものの規約（ステージ範囲・メッセージ・コミットしてよい3経路）は SKILL.md の `C-1`〜`C-13` が持ちます。本節は **push とタイミング**のみを定めます。

| # | 規則 |
|---|---|
| **GB-19** | `git push -u origin <branch>` のみを使う。**force push は絶対に行わない**（`--force` / `--force-with-lease` とも）。push 先は**本スキルが決定したブランチ1つ**に限り、他ブランチ・他リモートへは push しない |
| **GB-20** | タイミングは**コミットの直後**（複数タスクモードでは**タスクごと**）。**まとめて最後に push しない**（クラウドのコンテナは破棄されうるため、途中で落ちても完了分が残るようにする）。ネットワーク起因の失敗は **2s → 4s → 8s → 16s のバックオフで最大4回**リトライする。認証エラー・拒否（non-fast-forward・保護ブランチ等）は**リトライしない**（時間の経過で解消しないため） |
| **GB-21** | push に失敗しても**コミットを巻き戻さない**（`git reset` を使わない）。警告（7-5）を表示し、実行結果サマリと `dev-result.md` の `## 終了サマリ` の `- push:` 行へ記録して**続行**する（`E-38`）。複数タスクモードでは後続タスクへ進む。**後続の判断は利用者に委ねる** |
| **GB-22** | `push` が false で、かつ**未 push のコミットが残る**場合、実行の最後に警告を表示する。判別不能に由来する場合は 7-1 の文言を用いる。未 push の件数は上流がある場合 `git rev-list --count @{u}..HEAD`、無い場合は**本実行で作成したコミット数**で数える |
| **GB-23** | **複数タスクモードでは自動ブランチ作成を行わない**（`task1,task2,task3` は1つのブランチ名に対応しないため）。`branch.create` が true でも作成せず、警告（7-4）を表示して**起動時のブランチ**へタスクごとにコミットする。`commit` / `push` の設定は複数タスクモードでも有効 |

## 6. 安全境界【この表以外の git 操作は行わない】

| 無条件に許可（読み取り） | 条件付き許可（本ファイルの規約に従う場合のみ） | 禁止 |
|---|---|---|
| `git status --porcelain` / `git rev-parse` / `git diff` / `git diff --cached` / `git rev-list --count` / `git check-ref-format` / `git ls-remote --heads`（照会） | `git checkout -b <branch>` / `git checkout <branch>`（`GB-13`・実装着手前に1回だけ） | `git push --force` / `--force-with-lease` / 履歴の書き換え |
| — | `git fetch origin <branch>`（`GB-13` のリモート追跡作成時のみ） | `git reset` / `git checkout -- <path>` / `git restore` / `git clean`（**修正の巻き戻しを自動で行わない**） |
| — | `git add -- <明示パス>` / `git commit`（`C-1`〜`C-13`） | `git add -A` / `git add .` / `git commit -a` |
| — | `git push -u origin <branch>`（`GB-19`。決定したブランチのみ） | `git rebase` / `git merge` / `git tag` / `git config` / 他ブランチ・他リモートへの push |

## 7. 文言集【省略・要約禁止】

**7-1. 実行環境を判別できず、未 push のコミットが残る場合**:

```
⚠ 実行環境を判別できませんでした。push を行っていません。
  ブランチ <branch> に未 push のコミットが <n> 件あります。
  クラウドセッションの場合、コンテナ破棄とともに失われます。
  push するか、.claude/task-skills.json に "push": true を明示してください。
```

**7-2. `commit: false` かつ `push: true`（`GB-6`）**:

```
⚠ commit が false のため push は行いません（"push": true は無視されます）。
  コミットしない実行では push する対象が存在しないためです。設定ファイルは変更していません。
```

**7-3. 設定ファイルをパースできない（`GB-4`）**:

```
⚠ <ファイル名> を JSON として読み取れなかったため、この層の設定を無視しました。
  意図を読み取れない状態で遠隔へ反映しないため、この実行では push を行いません。
```

**7-4. 複数タスクモードでのブランチ作成の抑止（`GB-23`）**:

```
⚠ 複数タスク指定のため、タスク名からのブランチ作成は行いません（複数タスクは1つのブランチ名に対応しません）。
  現在のブランチ <branch> へ、タスクごとにコミットします。
```

**7-5. push に失敗した（`GB-21`）**:

```
⚠ push に失敗しました（<理由>。リトライ <n> 回）。コミットは巻き戻していません。
  ブランチ <branch> に未 push のコミットが <n> 件あります。手動で push してください:
    git push -u origin <branch>
```

**7-6. 既に別タスクの作業ブランチ上にいる（`GB-16`）**:

```
⚠ 現在のブランチ <current> を起点に <branch> を作成します。
  <current> のコミットが <branch> にも含まれます。別の起点から分岐したい場合は、中断して起点ブランチへ切り替えてから再実行してください。
```

**7-7. ブランチ名が不正（`GB-12`・`E-37`）**:

```
❌ ブランチ名 <branch> は git のブランチ名として不正です（git check-ref-format に不合格）。
   ブランチを作成せず、実装にも着手せずに終了します。
   タスク名を見直すか、.claude/task-skills.json の branch.prefix を調整してください。
```

**7-8. リモート照会に失敗した（`GB-13` 補足）**:

```
⚠ リモートの <branch> を照会できませんでした（<理由>）。ローカルに新規作成して続行します。
  同名のリモートブランチが存在する場合、後続の push は失敗します。
```
