# アセットのビルド（task-dev ステップB）

> **この文書は `task-dev` のステップB（アセットのビルド）に着手する時点で読み込みます。**
> ステップB は実装フェーズの末尾（`B-impl`）と、レビュー・修正ループの各修正パスの直後（`B-fix`）で実行します。
> 中断からの復帰で `## 終了サマリ` の `- ビルド:` が `失敗` だった場合（`R-10`）にも読み込みます。
>
> 本文中の規約 ID（`AB-1`〜`AB-20`）は SKILL.md 本体からの参照名です。変更しないでください。

## 位置づけ

`task-dev` は「実行境界」により、アプリ・テスト・開発環境を一切動かしません。**本書が定めるアセットのビルド（Sass / CSS・JS / TS のバンドル・トランスパイル・圧縮）だけが、その唯一の例外です。**

- **例外にする理由**: コンパイル後の CSS / JS をリポジトリで管理するプロジェクトでは、ビルドしないままコミットすると「ソースは新しいが配信物は古い」コミットができます。またコンパイルエラーは実装の欠陥であり、実装した主体が直すべきものです。`task-verify` まで持ち越すと、検証の周回を実装の手戻りに使うことになります。
- **例外にしてよい理由**: アセットのビルドは、ソースファイルを読んで出力ファイルを書くだけの処理です。開発環境・DB・アプリ本体のコード・認証情報を必要とせず、ホスト上の Node.js だけで完結します。クラウドセッションでも、ローカルセッションでも同じ手順で実行できます。
- **例外の範囲**: 実行してよいのは **`AB-6` の判定を通ったビルドスクリプト1本**と、**`AB-9` の依存のインストール1回**だけです。テスト・lint・型検査（ビルドの一部として組み込まれていない限り）・開発サーバ・watch・アプリのビルド（SSR / SSG）は、従来どおり実行しません。

**ビルドを実行するのは常にメイン会話です**（両モード共通）。実装・レビュー・修正の委譲先は、従来どおりビルドを実行しません（5-6-2 の禁止事項は緩めません）。

## AB-1〜AB-5: 対象の判定

| # | 規則 |
|---|---|
| **AB-1** | **ビルド入力**とは、拡張子が `.scss` / `.sass` / `.less` / `.styl` / `.css` / `.pcss` / `.js` / `.mjs` / `.cjs` / `.jsx` / `.ts` / `.mts` / `.cts` / `.tsx` / `.vue` / `.svelte` のファイル、およびビルド設定（`package.json` の `scripts` 以外の変更・`webpack.config.*` / `vite.config.*` / `rollup.config.*` / `postcss.config.*` / `tailwind.config.*` / `babel.config.*` / `.babelrc*` / `tsconfig*.json` / `gulpfile.*` / `.browserslistrc`）である |
| **AB-2** | **ビルド単位**は、`changed_by_skill` に含まれるビルド入力ごとに、そのファイルから上へ辿って最初に見つかる `package.json`（プロジェクトルートを越えない）のディレクトリとする。`node_modules/**` / `vendor/**` / `.claude/**` 配下のファイルはビルド入力に数えない。複数のビルド単位が見つかれば、パスの辞書順に1つずつ処理する |
| **AB-3** | ビルド単位が0件なら **`対象なし`** として記録し、何も実行しない（ビルド入力を変更していない、または `package.json` を持たないプロジェクト） |
| **AB-4** | `B-fix` では、**その修正パスで変更したパス**に含まれるビルド入力だけで AB-2 を評価する（変更が無ければ `B-fix` は何も実行せず、直前の結果を引き継ぐ） |
| **AB-5** | `package.json` / ロックファイルを本タスクが変更している（依存の追加・更新を含む）ビルド単位は **`実行不能（依存の変更を含む）`** とする。ロックファイルの更新は `task-dev` が行わない操作であり（手編集は 5-16 で禁止）、ロックファイルと食い違ったまま入れた依存でビルドしても結果に意味がないため |

## AB-6〜AB-8: ビルドスクリプトの選択と安全確認【実行前に必ず読んで確かめる】

| # | 規則 |
|---|---|
| **AB-6** | **スクリプトの選択**: ビルド単位の `package.json` の `scripts` から、次の順で最初に存在する1本を選ぶ: ① `build` ② `production` / `prod` ③ `build:css` と `build:js` の両方（この場合のみ2本を順に実行する）④ `build:css` または `build:js` または `css` / `sass` / `scss` / `js` のいずれか1本（ビルド入力の種類に合うもの）。**`dev` / `start` / `serve` / `watch` / `preview` / `test` / `lint` / `deploy` / `release` / `publish` を名前に含むものは選ばない**。該当が無ければ **`実行不能（ビルドスクリプトが無い）`** |
| **AB-7** | **安全確認（読み取りのみ・省略不可）**: 選んだスクリプトの本文を読み、`npm run <x>` / `yarn <x>` / `pnpm run <x>` / `run-s` / `run-p` / `npm-run-all` / `concurrently` が呼ぶ先も含めて**展開した全コマンド**が、次の**許可ツール**だけで構成されることを確かめる: `sass` / `node-sass` / `less`（`lessc`）/ `stylus` / `postcss` / `tailwindcss` / `webpack`（`serve` を除く）/ `vite build` / `rollup` / `esbuild` / `parcel build` / `tsc` / `babel` / `swc` / `terser` / `uglifyjs` / `cleancss` / `csso` / `wp-scripts build` / `mix`（`laravel-mix`。`watch` / `hot` を除く）/ `gulp` / `grunt` / `node <ファイル>`（後2者と `node` は AB-8 を満たす場合のみ）/ 補助（`cross-env` / `rimraf` / `del-cli` / `mkdirp` / `cpx` / `copyfiles` / `shx` / `echo` / `&&` / `\|\|` / `;`）。**それ以外のコマンド（`php` / `wp` / `ddev` / `docker` / `curl` / `wget` / `ssh` / `scp` / `rsync` / `ftp` / `git` / `npx <未知のパッケージ>` / `next` / `nuxt` / `gatsby` / `astro` / `remix` / `svelte-kit` など）を1つでも含めば実行しない**。`--watch` / `-w` / `serve` / `--hot` を含む場合も実行しない。いずれも **`見送り（安全確認: <理由>）`** |
| **AB-8** | **設定ファイルの確認**: `webpack.config.*` / `vite.config.*` / `rollup.config.*` / `gulpfile.*` / `Gruntfile.*` / `webpack.mix.js` / `node <ファイル>` の対象ファイルを読み、**外部へ送る処理**（`http` / `https` / `net` / `child_process` / `fetch` / `axios` の使用、名前に `upload` / `deploy` / `ftp` / `sftp` / `s3` / `sentry` / `bugsnag` / `datadog` / `browser-sync` / `livereload` / `notifier` を含むプラグインの読み込み）が無いことを確かめる。あれば **`見送り（安全確認: <ファイル>: <該当箇所>）`**。アプリのビルド（SSR / SSG）に該当するフレームワークは、ビルド時にアプリ本体のコード・DB・外部 API を実行しうるため対象外である |

> **「見送り」は失敗ではありません。** 安全を確かめられないビルドを実行しないのは本スキルの安全境界であり、コミットは妨げません（`AB-17`）。見送ったビルドは `task-verify` が遮断層の内側で実行します。

## AB-9〜AB-12: 実行

| # | 規則 |
|---|---|
| **AB-9** | **Node.js とパッケージマネージャ**: `command -v node` が失敗すれば **`実行不能（Node.js が無い）`**（Node.js を自分でインストールしない。DDEV 等のコンテナ内にしか Node.js が無いプロジェクトもこれに当たり、`task-verify` が遮断層の内側でビルドする）。パッケージマネージャはロックファイルで決める: `package-lock.json` → `npm` ／ `yarn.lock` → `yarn` ／ `pnpm-lock.yaml` → `pnpm`（コマンドが無ければ `実行不能（<名前> が無い）`）。`.nvmrc` / `.node-version` / `engines.node` があり実行中の Node.js と合わない場合は、警告して続行し記録へ残す |
| **AB-10** | **依存のインストール**: ビルド単位に `node_modules/` が**存在しない場合に限り**、ロックファイルどおりに1回だけインストールする（`npm ci` ／ `yarn install --frozen-lockfile`（Yarn 2 以降は `yarn install --immutable`）／ `pnpm install --frozen-lockfile`）。**ロックファイルが無ければインストールせず `実行不能（ロックファイルが無い）`**（解決結果が実行ごとに変わり、ロックファイルが新たに作られるため）。ビルド単位の `package.json` が `preinstall` / `install` / `postinstall` / `prepare` を持つ場合は `--ignore-scripts` を付ける（`prepare` で `husky install` が `git config` を書き換えるなど、プロジェクト定義のスクリプトを避けるため）。`node_modules/` が**既に存在する場合はインストールしない**（ローカルセッションで利用者の環境を作り直さない）。インストールが失敗すれば **`実行不能（依存のインストールに失敗）`** |
| **AB-11** | **実行の形**: `cd <ビルド単位> && CI=true npm_config_fund=false npm_config_audit=false npm_config_update_notifier=false <npm run / yarn / pnpm run> <スクリプト>`。`Bash` の `timeout` は 600000ms を明示する。`run_in_background` は使わない。**`ddev exec` / `docker compose exec` などで環境の中から実行しない**（開発環境の起動・接続は引き続き禁止） |
| **AB-12** | **失敗の振り分け**: 終了コードが非0のとき、出力が**本タスクの変更したファイル（`changed_by_skill`）のパスと行**を指していればコードの欠陥として **`失敗`** とし、AB-13 の修正へ進む。モジュール・ネイティブバイナリの欠落、Node.js のバージョン不一致、ネットワーク・権限・メモリ不足など**環境に起因する失敗**は **`実行不能（<要旨>）`** とし、修正しない（コードの修正で環境の問題を回避しない）。判別できなければ `失敗` へ倒す（欠陥を見逃さない側） |

## AB-13〜AB-15: ビルドエラーの修正

| # | 規則 |
|---|---|
| **AB-13** | **修正の上限**: 1回のステップB につき、`失敗` を受けた修正は**最大2回**（ビルドの実行は初回を含め最大3回）。2回修正してもなお `失敗` なら、その結果を確定させる（`E-40`） |
| **AB-14** | **修正の主体**: 単一タスクモードではメイン会話が直接直す。複数タスクモードでは、下記の**ビルド修正委譲**（`name` なしの同期 `Agent` 委譲）へ渡す。いずれも、直してよいのは**ビルドの出力が指す箇所だけ**である（レビュー指摘に紐づかない変更の禁止の例外は、この1点に限る）。5-16 の書き込み禁止対象は変更しない |
| **AB-15** | **修正したパスの扱い**: 修正したパスは `changed_by_skill` へ加える。`B-fix` での修正は、その修正パスの「修正で変更されたパス」に含めて `RS-8` の修正差分を算出する（**次のレビューパスがビルド修正も見る**）。`B-impl` での修正は実装フェーズの一部であり、1周目のレビュー（出し切り）の対象になる |

**ビルド修正委譲プロンプト**【逐語・複数タスクモードのみ】:

```
あなたはビルドエラーの修正担当です。以下のビルドの失敗を、出力が指す箇所だけを直して解消してください。

プロジェクトルート: <PROJECT_ROOT>
対象タスク: <TASK>
ビルド単位: <ビルド単位のリポジトリ相対パス>
実行したスクリプト: <スクリプト名>

【ビルドの出力（末尾 60 行まで）】
<ビルドの標準出力・標準エラー出力の末尾>

【書き込み禁止対象（逐語）】.git/** / .claude/tasks/<TASK>/req.md / .claude/tasks/<TASK>/design.md / 他タスクのディレクトリ / プロジェクトルートの外 / node_modules/** / vendor/** / .env 等の認証情報・秘密鍵・証明書・トークン / ロックファイルの手編集 / package.json / ビルドの出力先のファイル。

【コード コメントの規範（逐語）】コメントはコードを読んでも復元できないことだけに書くこと。何をしているかの説明、名前の言い換え、区切りの装飾コメントは書かないこと。書いてよいのは、非自明な制約・外部仕様の参照・回避した既知の不具合・意図的に残した限界とその解除条件に限る。コメント密度は当該ファイルの既存水準を超えないこと（新規ファイルなら同一ディレクトリ内で最も近い既存ファイルに合わせる）。説明がコードより長くなったら、説明ではなくコードのほうを直すこと。

【戻り値フォーマット（厳守）】応答の最後に ```json フェンスで囲んだオブジェクトを 1 つだけ出力すること。前置きの散文を書かないこと。キーは status（success / failure）, files（変更したファイルのリポジトリ相対パスの配列。必須・空配列可）, summary（1〜2 文）。任意で reason。

【禁止事項（逐語）】ビルドを含め、プロジェクトのコード・スクリプトを実行しない（ビルドの再実行は呼び出し元が行う）。開発環境の起動・停止と既存環境への接続、DB への接続、外部への通信（パッケージのインストールを含む）を行わない。git の状態を変更する操作を一切行わない。他タスクのディレクトリに触れない。進捗管理用の Task ツールを使用しない。AskUserQuestion を使用しない。さらに別のサブエージェントを spawn しない。dev-result.md へ書き込まない（記録は呼び出し元が行う）。ビルドの出力が指す箇所以外を変更しない。
```

戻り値は 5-6-3 の `RV-1`〜`RV-3`・`RV-5`・`RV-6` で検証します（`files` は必須）。未受領・再委譲後も形式不正なら、その時点の結果を `失敗` として確定させます（`E-40`）。`files` が空配列なら修正できなかったものとして、残りの修正回数を使わず `失敗` で確定させます。

## AB-16〜AB-18: 出力の扱いとコミット

| # | 規則 |
|---|---|
| **AB-16** | **出力の特定**: ビルドの直前と直後に `git status --porcelain=v1 --untracked-files=all` を取り、**直後にだけ現れた、または内容が変わったパス**のうち、`changed_by_skill` / `baseline_dirty` / `node_modules/**` / `.claude/tasks/**` / ロックファイル / `package.json` を除いたものを **`build_outputs`** とする。git が無視する（`.gitignore` 対象の）出力は status に現れないため、自然に除外される。**ビルド単位の外に現れたパス**と、**ロックファイル・`package.json` の変化**は `build_outputs` へ入れず、警告して記録する |
| **AB-17** | **コミット**: `build_outputs` はコミット対象（`C-9` の和集合）へ加える。**レビュー対象（`RS-1`）には加えない**（生成物であり、レビューはそのソースを見る）。`G-1` の dirty 判定からは `changed_by_skill` と同様に除外する。ビルドの最終結果が **`失敗` の場合はコミットしない**（`E-40`）。`対象なし` / `実行不能` / `見送り` はコミットを妨げない（ソースは変わらず、ビルドは `task-verify` が引き継ぐ） |
| **AB-18** | **出力を消さない・戻さない**: ビルドが途中で失敗して出力が半端に書き換わっていても、`git restore` / `git checkout -- <path>` で戻さない（`C-7`）。`失敗` で確定した場合は、`build_outputs` に挙がったパスを中断時の告知へ列挙する |

## AB-19〜AB-20: 記録

| # | 規則 |
|---|---|
| **AB-19** | **`dev-result.md` への記録**: 実装フェーズ（`B-impl`）の結果は `## 動作確認結果` へ、ビルド単位ごとに `- アセットのビルド: <ビルド単位> / <スクリプト> / <結果> / インストール: <した（コマンド） / しなかった（node_modules あり） / —> / 修正: <回数>` の形で書く。`B-fix` の結果は `### ループ N` の `- ビルド（B-fix）:` 行へ書く。**最終結果**は `## 終了サマリ` の `- ビルド:` 行（W-6 の上書き更新）へ書く。最終結果は、ビルド単位ごとの直近の結果を集約し、`失敗` が1つでもあれば `失敗`、それ以外は `成功` / `対象なし` / `実行不能（…）` / `見送り（…）` をビルド単位ごとに列挙する |
| **AB-20** | **記録しないもの**: ビルドの出力を `dev-result.md` へ全文転記しない（失敗時に末尾の数行の要旨のみ）。環境変数の値・トークン・内部ホスト名を出力から転記しない |
