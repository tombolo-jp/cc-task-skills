# 要件定義書の更新（要確認事項の反映）

あなたは経験豊富なビジネスアナリストです。要件定義書（req.md）末尾の「要確認事項」セクションに対するユーザーの回答を本文へ反映し、req.md を詳細設計に進められる確定版へ整理します。

タスク「$ARGUMENTS[0]」の要件定義書を更新します。

## 引数の解釈

このスキルは以下の引数を受け取ります:

- **第1引数（タスク名）**: `$ARGUMENTS[0]` — 必須。処理対象のタスク名。
- **オプション**: 第2引数以降に `--team` などのフラグが指定される場合があります。

### オプション一覧

| オプション | 説明 |
|-----------|------|
| `--team` | Agent Teams を有効化し、チームメイトと協調して作業を実行します |

**引数全体**: `$ARGUMENTS`

### 重要: `--team` の有無による分岐【最優先】

引数全体に `--team` が含まれるかを最初に判定してください。これがスキル全体の挙動を決める最上位フラグです。

- **含まれない場合**:
  - 「Agent Teams モード」節は完全に無視してください
  - 起動時メッセージ（`✅` / `⚠️`）は一切表示しないでください
  - Agent Teams 関連操作（ToolSearch 等）は一切実行しないでください
  - メタ情報の Agent Teams は `無効（指定なし）` と記録してください
  - 「手順」セクションへ進んでください
- **含まれる場合のみ**:
  - 「Agent Teams モード」節へ進んでください

## Agent Teams モード

> **【前提】このセクションは `--team` 指定時のみ評価します。未指定なら読まずに「手順」セクションへ進んでください。**

### チームメイトの起動（--team 指定時のみ）

Agent Teams は `Agent` ツールでチームメイトを spawn し、各 teammate の成果を `Agent` の **戻り値**（最終メッセージが tool result として返る）で収集し、`TaskCreate` / `TaskUpdate` で進捗を共有する暗黙チーム方式で実行します。`SendMessage`（teammate 間のライブ通信）は **環境変数 `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS` が有効なときのみ利用できる任意機能**であり、使えれば指示・連絡に併用してかまいませんが、使えなくても上記の戻り値方式で成立します。

（注: 旧来の `TeamCreate` / `TeamDelete` は廃止済みのため使用しません。`Agent` は core ツールでメイン会話に常在するため、ToolSearch でのロードは不要です。）

#### 協調ツールのロード（任意）

進捗共有・ライブ通信を使う場合は、以下でスキーマをロードしてください（`Agent` 自体は常在のため不要です）:

```
ToolSearch query="select:TaskCreate,TaskUpdate,SendMessage" max_results=10
```

`SendMessage` が `<functions>` ブロックに含まれない場合は環境変数が無効です。その場合も `Agent` の戻り値方式で続行してかまいません（フォールバックは不要です）。

#### ⚠️ コストに関する注意

Agent Teams はトークン消費が通常の2〜5倍に増加する可能性があります。

#### チームメイトの spawn と稼働確認

1. 各担当を `Agent` ツールで spawn してください（`subagent_type` を指定。`SendMessage` を併用する場合は `name` を付与して宛先を指定できるようにします）。独立した作業は、同一メッセージ内に複数の `Agent` 呼び出しを並べて並列起動してください。
2. **チームメイトが少なくとも 1 体、実際に稼働（応答）したことを確認してください。**
3. 進捗共有は `TaskCreate` / `TaskUpdate` で行います。`SendMessage` が利用可能なら作業指示・連絡に併用してください（任意）。各 teammate の成果は `Agent` の戻り値で受け取ります。
4. 全成果の統合後、明示的なチーム破棄は不要です（自動クリーンアップ）。

#### spawn 失敗時のフォールバック【必須】

spawn したチームメイトが 1 体も稼働しなかった場合は、以下を必ず実行してください:

1. 次のメッセージを表示する（省略・要約禁止）:

   > ⚠️ Agent Teams（チームメイトの起動）が現在の環境で利用できないため、Agent Teams モードを起動できません。今回は通常モードで実行します。

2. 以降の Agent Teams 関連手順を一切実行しない
3. 「手順」セクションへ進み、単一エージェントとして通常通り作業する
4. メタ情報の Agent Teams は `無効（フォールバック）` と記録する

#### 役割分担

チームメイトに以下の並行作業を依頼してください:

1. **返信反映担当**: 「要確認事項」の解決済み項目（子要素あり）について、ユーザー回答の内容を req.md 本文の該当セクションへ反映する設計を検討。本文の対応マーカー「（要確認）」を確定内容へ置換する方針をまとめる。
2. **整理・確定担当**: req.md を詳細設計（task-design）に必要な情報だけを残す形へ整理（不要な検討経緯・重複記述・暫定表現の削除・簡潔化）する方針を検討。確定要件・非機能要件・制約は保持対象とする。

**重要**: 各チームメイトが同じ本文セクションを同時に編集しないよう、対象セクション単位で作業を分割してください。

#### 統合

チームリード（あなた）は両担当の結果を統合し、未解決項目の残置判定と「要確認事項」セクションの縮小/削除を行った上で、最終的な req.md を確定してください。

> **注**: チームメイトが稼働せず、結果としてチームリード（あなた）が一人で全作業を完遂した場合、それは Agent Teams 実行が成立していない状態です。メタ情報は `無効（フォールバック）` と記録してください。

## パス解決ルール

**重要**: タスクファイルはプロジェクトルート配下に格納されています（`~/.claude/tasks/` ではありません）。

最初に Bash ツールで `pwd` を実行し、プロジェクトルートの絶対パスを取得してください。
以降のすべてのファイルパスは、取得したプロジェクトルートを先頭に付けた絶対パスで指定してください。

例: `pwd` → `/Users/yuki/dev/www/my-project` の場合
- `<PROJECT_ROOT>/.claude/tasks/$ARGUMENTS[0]/req.md` → `/Users/yuki/dev/www/my-project/.claude/tasks/$ARGUMENTS[0]/req.md`

## 手順

### ステップ0: 全フェーズを Task に登録する【FR-1: フロー強制】

本スキルの手順に着手する前に、まず以下の全フェーズを `TaskCreate` で一括登録してください。
登録順に実行し、どのフェーズもスキップ・前倒しをしないこと。各フェーズは着手直前に
`TaskUpdate` で `in_progress`、完了直後に `completed` へ更新します。

登録するフェーズ（この順序・各 subject は imperative 形）:

1. プロジェクトルートを pwd で解決する
2. req.md を読み込み「要確認事項」セクションを解析する
3. 各項目の解決/未解決を判定する（子要素の有無）
4. 解決済み項目を本文へ反映し当該項目を削除する
5. req.md を task-design 必要情報へ整理する
6. 未解決項目を残置しセクション/メタ情報を更新する
7. 未解決件数を提示し完了報告する

> **Task ツールが利用できない場合のフォールバック**: `TaskCreate` / `TaskUpdate` が
> 当該環境で利用できない場合は、上記フェーズ一覧を本文中のチェックリスト（`- [ ]`）として
> 保持し、各フェーズ完了を明示しながら順守してください。Task ツールの不在を理由に
> フェーズを省略しないこと。Task ツールの可用性は `ToolSearch query="select:TaskCreate,TaskUpdate"`
> で判定し、`<functions>` ブロックに両方が含まれれば利用可、含まれない／ToolSearch が
> エラー終了した場合は利用不可としてチェックリストへフォールバックします。フォールバック時は
> 「Task ツールが使えないため地の文チェックリストで進行します」と1行表示してから続行してください。
>
> **`--team` 有効時**: Agent Teams が成立している場合は、チーム共有タスクリスト上で
> 各フェーズを Task として扱います（フェーズ=親、todo 項目=子）。独自のフェーズ追跡は
> 共有タスクリストに統合してください。

### ステップ1: req.md の読み込みと「要確認事項」の解析

1. Read ツールで `<PROJECT_ROOT>/.claude/tasks/$ARGUMENTS[0]/req.md` を読み込みます。
   - **req.md が存在しない場合**: 「`.claude/tasks/$ARGUMENTS[0]/req.md` が見つかりません。task-req を先に実行してください。」と表示し、中断します（ファイルは作成・破壊しない）。
2. 末尾の「要確認事項」セクション（`## 要確認事項`）を特定します。
   - **「要確認事項」セクションが存在しない場合**: 「req.md に『要確認事項』セクションがありません。task-req で要確認事項を出力済みか確認してください。」と表示します。本文整理（ステップ4）のみ任意で実施するか、何もせず終了します。req.md は破壊しません。

### ステップ2: 各項目の解決/未解決を判定する

「要確認事項」セクション内の各トップレベル箇条書き項目（`- ` で始まる項目）について、解決/未解決を判定します:

- 当該項目の**直下にインデントされた子要素（ネストされた `- ` 箇条書き）が存在すれば「返信あり（解決済み）」**とみなします。
- 子要素が存在しなければ「未返信（未解決）」とみなします。

```
要確認事項の構造例:

## 要確認事項
- 認証方式は OAuth2 と Session のどちらを採用するか   ← 子要素なし = 未解決
- 対応ブラウザの最小バージョンは何か
  - Chrome/Edge/Safari の最新2バージョンを対象とする   ← 子要素あり = 解決済み
```

- **子要素の回答が曖昧、または本文の反映先が特定できない場合**は、「解決済み」と即断せず、未解決として残置し、その旨を完了メッセージで注記します（過剰反映を避ける保守的方針）。

### ステップ3: 解決済み項目を本文へ反映し当該項目を削除する

各「解決済み項目」について:

1. 子要素（ユーザー回答）の内容を req.md の**該当本文セクションへ反映**します。
2. 本文の対応マーカー「（要確認）」を確定内容へ置換します。
3. 反映が完了した項目を「要確認事項」セクションから**削除**します。

### ステップ4: req.md を task-design 必要情報へ整理する

req.md を**詳細設計（task-design）に必要な情報だけを残す**形へ整理します:

- 不要な検討経緯・重複記述・確定済みの暫定表現（「〜かもしれない」等）を削除・簡潔化します。
- **ただし本文の確定要件（機能要件・非機能要件・制約等）は必ず保持**し、過度な削除で情報を欠落させないでください。判断に迷う内容は削除せず残します（データ欠落 < 冗長 の優先度）。

### ステップ5: 未解決項目を残置しセクション/メタ情報を更新する

1. **未解決項目**は「要確認事項」セクションにそのまま残置します。
2. **セクション削除条件**: 全項目が解決済みで残置ゼロになった場合、「要確認事項」セクション自体を削除します。
3. セクション順序は末尾を **「要確認事項」→「メタ情報」**（メタ情報を最下部）に保ちます。「要確認事項」を削除した場合は「メタ情報」が末尾になります。
4. メタ情報セクションを今回の実行内容で更新します（実行モデル・実行日時・Agent Teams）。

## 冪等性について

同じ req.md に対する再実行は、未解決項目に子要素（回答）が増えていなければ結果を変えません
（解決済みは既に本文反映済みで消滅、未解決はそのまま残置）。これにより「回答→再実行」ループを
安全に反復できます。未解決が残る限り、ユーザーが回答を追記して再実行する運用を繰り返せます。

## 完了後

未解決件数に応じて、次のいずれかのメッセージを表示してください:

| 状況 | メッセージ |
|------|-----------|
| 未解決なし（全解決・セクション削除） | 「要確認事項はすべて解決済みです。req.md を確定版に整理しました。`/task-design $ARGUMENTS[0]` へ進めます。」 |
| 未解決あり | 「要確認事項のうち N 件が未解決です。req.md 末尾の『要確認事項』セクションに各項目へインデント返信で回答したうえで、`/task-req-update $ARGUMENTS[0]` を再実行してください。」 |
| 要確認事項セクション自体が存在しない | 「req.md に『要確認事項』セクションがありません。task-req で要確認事項を出力済みか確認してください。」 |

req.md 末尾のメタ情報セクションを、以下の形式で更新してください:

## メタ情報
- 実行モデル: [あなたが動作しているモデル名を正確に記載]
- 実行日時: [現在の日時]
- Agent Teams: [有効 / 無効（指定なし） / 無効（フォールバック）]
